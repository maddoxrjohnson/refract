# 20. Codex runs as an overflow agent beside Claude, gated by AGENTS.md readiness

Status: accepted

**Context.** A Claude Code plan has a 5-hour and a weekly limit. When one runs out mid-milestone, work stops until it resets, though a second agent with its own quota, Codex CLI, could carry on from the same handoff note. Codex reads `AGENTS.md`, not `CLAUDE.md`, ignores `@path` imports, has no AskUserQuestion or plan mode, and keeps its own session files. A repo whose rules live only in `CLAUDE.md`, or whose handoff says "use AskUserQuestion", reads wrongly to Codex. Two agents editing one working tree at once would trip over each other, and whichever picks up needs to know where the other stopped.

**Decision.** Refract treats Codex as a second agent kind beside Claude. The helper finds `codex` in WSL, reads Codex rollouts as sessions, and tells which process runs which session from the lock file the process holds (Refract launches with `--no-daemon` so the process it starts holds it). Each repo gets a readiness state from its instruction files and live sessions: Not ready (no or unsynced `AGENTS.md`, `@` imports, over 32 KiB) and Busy (the other agent working or waiting on you) block a launch; Claude-only lines in `AGENTS.md` or the notes it names only warn. The picker offers both agents in one list. It preselects New Codex agent when Claude's plan use is at or over a threshold (default 95 %), and a briefed New agent when the other agent worked in the repo last. A brief tells the new agent to follow the handoff, how the other session ended, its last message, and to check `git status` and `git diff` first. An idle other agent can be stopped from the picker before starting. A Make Codex-ready button launches an agent with a fixed prompt that moves the shared rules into `AGENTS.md`, leaves `CLAUDE.md` as `@AGENTS.md` plus a Claude-only section, and never commits or edits `.gitignore`. Codex's model, effort and global rules come from the user's own Codex setup, not from Refract.

**Consequences.** When Claude runs out, Enter on a ready repo starts Codex with a brief, and when Claude is back, Enter starts Claude briefed on what Codex did, including any branch it left for review. Nothing changes for someone without Codex. A repo needs a one-off `AGENTS.md` split before Codex can be launched there. Without the status hook a live Claude session's state is unknown, so it counts as busy and blocks Codex in that repo; stopping it from the picker is then not offered. A Codex session has no status hook yet, so it is working while a turn is open and idle otherwise. A Codex started outside Refract in daemon mode is found through the daemon's lock, but one that hasn't had its first message isn't shown, since its folder is unknown. Codex's own limits aren't read yet, so the nudge only looks at Claude.

**Alternatives considered.**
- **Generate `AGENTS.md` from `CLAUDE.md` in Refract.** No setup for the user, but Refract would be writing instruction files on its own, and a generated copy goes stale. An agent doing the split once, which the user reviews, keeps one source.
- **Warnings only, never block.** Simpler, but a missing `AGENTS.md` means Codex starts with none of the repo's rules, and two agents at once in one tree can lose work. Those block; wording problems only warn.
- **Switch automatically when Claude runs out.** The person may want to wait for the reset or finish by hand. A preselected row with its reason keeps the choice one key away.
- **Track Codex sessions by the newest rollout per folder.** Works without `--no-daemon`, but guesses wrong with two sessions in one folder and can't see a session before its first message. The held lock file names the session from the start.
