# 16. Go to the running agent, found by its window's folder and process ancestry

Status: accepted

**Context.** Pressing Enter on a clean repo started a new agent at once, even while one was still running there. The person usually wanted the agent they already had, so they got a second one beside it. VS Code's `code` command can bring a folder's window to the front but cannot say which terminal tab to show, and Claude Code's session id is not visible from inside VS Code's extension API.

**Decision.** The Refract extension sets `REFRACT_FOLDER` to its window's single folder on every terminal the window starts. A live session is "focusable" when the helper knows its `claude` process for certain (the process names the session id, or is the only one in the repo naming none) and that process's `REFRACT_FOLDER` is exactly the repo path. While a repo has one, the picker always shows and lists "Go to the running agent" first; when the newest one waits on the person, it is preselected, ahead of Resume. Choosing it sends `prepareLaunch` with mode `focus`. The helper checks the pid still runs `claude` with the start time it recorded, then writes a request with an empty `argv` and `focus: {sessionId, pids}`, where `pids` is the process and its ancestors from `/proc/<pid>/stat`. The app runs the usual `code --profile Refract --folder-uri`, which raises the window, and the extension shows the terminal whose `processId` (its shell) is in that chain. It never creates a terminal for a focus request, and drops one that arrives late instead of asking.

**Consequences.** Requiring the window's own folder means `code --folder-uri` raises the window the agent is in, rather than opening an empty one: agents in other editors (Insiders, Cursor, VSCodium, whose servers lack the extension), in multi-root windows or in a window on a parent folder are not offered. Matching by ancestry needs no change to how `claude` starts and works for agents started by hand. Agents started before extension 0.1.3, or before their window reloaded with it, have no `REFRACT_FOLDER` and are not offered until they are restarted. A window still running 0.1.2 ignores focus requests until it is reloaded, so until then the window comes forward without switching tabs. An agent under `tmux` or `screen` may carry the variable but descends from the multiplexer's server, not the terminal's shell, so nothing matches and the extension only logs it. Two agents started without an id in the same repo are both live but neither is offered, since which terminal runs which is a guess. A new agent that has not been sent a prompt yet has no transcript, so it is not a session the helper lists and is not offered either. The extension version went to 0.1.3, so the app reinstalls it on the next launch.
